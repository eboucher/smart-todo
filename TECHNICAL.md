# 🛠️ Technical Deep Dive: How Smart Todo Works

This document explains the inner workings of the `smart-todo` CLI. It breaks down how Rust features and crates interact to create the application.

## 1. Architecture Overview

The application follows a simple **MVC-like (Model-View-Controller)** pattern, adapted for a CLI:

- **Model (`src/todo.rs`)**: Defines *what* a Task is (Data definition).
- **View (`src/main.rs`)**: Handles *input* (CLI args) and *output* (Terminal printing).
- **Storage (`src/storage.rs`)**: Handles *persistence* (Saving/Loading JSON).

## 2. The Crates (Libraries)

We use three powerful crates to avoid reinventing the wheel:

| Crate | Purpose | How we use it |
|-------|---------|---------------|
| **`clap`** | CLI Parsing | Turns our `enum Commands` into actual `--flags` and subcommands. |
| **`serde`** | Serialization | "Serializer/Deserializer". Magically converts Rust structs to JSON string (`Serialize`) and back (`Deserialize`). |
| **`colored`** | UI | Allows strings to be painted like `"High".red()`. |

## 3. Code Breakdown

### A. The Data Model (`src/todo.rs`)
We use **Derive Macros** (`#[derive(...)]`) to generate code automatically.

```rust
#[derive(Debug, Serialize, Deserialize)] // <--- Magic happens here
pub struct Todo {
    pub id: usize,
    pub title: String,
    pub priority: Priority,
    pub done: bool,
}
```
- `Serialize`: Tells `serde`: "If I want to save this, convert it to `{ "id": 1, ... }`".
- `Deserialize`: Tells `serde`: "If you see JSON, allow creating a Struct from it".

### B. Storage (`src/storage.rs`)
This module handles the "Database" (which is just a `todos.json` file).

**Loading Logic (`load_todos`):**
1. Check if `todos.json` exists using `std::path::Path::exists`.
2. If **No**: Return an empty Vector `Vec::new()`.
3. If **Yes**:
   - Read file to string: `fs::read_to_string`.
   - Parse JSON: `serde_json::from_str`.
   - **Error Handling**: We currently use `.expect()` which crashes if the JSON is corrupt. In a production app, we would handle this gracefully.

### C. The CLI Controller (`src/main.rs`)
This file drives the application.

1. **Parsing**:
   ```rust
   let cli = Cli::parse(); // logic generated by Clap
   ```
2. **Matching**:
   We use Rust's powerful `match` statement to handle commands:
   ```rust
   match cli.command {
       Commands::Add { ... } => { /* logic */ },
       Commands::List => { /* logic */ },
       ...
   }
   ```

## 4. Key Rust Concepts Used

- **Ownership & Borrowing**:
  - We pass `&todos` (immutable reference) to `save_todos` because saving doesn't need to consume or change the list.
  - We use `&mut todos` when finding a task to mark as done, so we can modify it in place.
- **Enums**: `Priority` is an enum, ensuring type safety. You can't set a priority to "Urgent" if strictly defined as "Low/Medium/High".
- **Result Output**: We return `Result<(), Error>` implicitly in main logic (though we handle panic with `expect` for simplicity this tutorial).

## 5. Data Flow (Example: `todo add`)

1. User runs `todo add "Buy Milk"`
2. **Clap** creates a `Commands::Add` variant.
3. **Main** calls `load_todos()` -> Reads file -> Deserializes to `Vec<Todo>`.
4. **Main** creates a new `Todo` struct instance.
5. **Main** pushes it to the vector: `todos.push(new_todo)`.
6. **Main** calls `save_todos(&todos)` -> Serializes to JSON -> Writes file.
7. **Main** prints success message.
